# ui_rover MVP — Capture, Palette Mock, Library Implementation Plan

## Overview

First feature release of ui_rover: a client-only swipe file for Instagram and Threads posts. Mia pastes a post URL plus one or more screenshots, marks the entry as **palette** or **design**, and it lands in a browsable library persisted in IndexedDB with JSON export/import. Palette entries get their colors extracted in the browser and painted onto a grayscale **wireframe mock** (web + mobile frames, e-commerce homepage sections) where every block is a touchpoint to reassign its color. Design entries are stored as framed screenshots with tags and notes.

## Problem Statement

Saved posts on Instagram/Threads are a dead end: no search, no tags, no way to see a palette applied to a real layout, and the platforms block anonymous fetches so nothing can be automated. ui_rover makes the URL the bookmark key and the screenshot the source of truth, so the library works without any Meta API (ARCHI.md §2, §5.1).

## Discovery decisions (from Step 1)

- **Palette mock structure (Mia's spec, 2026-09-15):** two block-level grayscale wireframes side by side — **Web** and **Mobile** — built from the mobile-first e-commerce homepage sections: search bar, hero (visual + primary CTA + promo), category row, sale banner (offer + CTA + countdown), featured product cards (image, price, wishlist, add-to-cart), social proof strip, bottom nav / footer. Palette colors replace the gray tones. **Each block is a touchpoint:** click it to change its color.
- **Multiple images per entry** (Instagram carousels): ordered image list; palette extracts from a chosen *source image* (default: first).
- **An entry cannot exist without at least one image.** A URL alone never creates an entry — direct consequence of the no-API constraint (the URL is a key, the screenshot is the data). Save stays disabled until URL is valid *and* ≥1 image is present.
- **Touchpoint = "clicking a block changes its color" (Mia's words).** Default click behavior applies the picked color to the block's *role* (so web + mobile frames stay coherent); the same popover offers **"just this block"** for a per-block override. Both are persisted. Mia can flip the default at Step 4 if she wants per-block first.
- **Extracted swatches are editable.** Real IG palette posts are cards with white margins, hex labels and watermarks; a blind 8-bucket quantize returns chrome. So the swatch strip supports remove, add-by-hex, and **pick-from-image** (click the source image → sample that pixel). Minimum useful palette is 3 colors; below that the mock still renders but shows a "palette too small — add colors" notice.
- **Design-entry "mock-up" — undecided by Mia ("not sure").** v0.1.0 builds a design entry as its screenshots in a mobile device frame with tags/notes/source link. **Mia's Step 4 decision: build "Extract palette" on design entries** — reuses the pipeline and shows the same wireframe mock; entry stays `kind: 'design'`.
- **Mock templates (Mia, second reference set):** she wants to see palettes on *different* layouts, not only the e-commerce homepage, and to see **code/UI components in a frame**. So the mock is a **template picker** over one block-spec format. v0.1.0 templates: `ecommerce` (her web + mobile pair, the default), `classic` (header / nav / hero / 3-col content / footer), `dashboard` (sidebar menu / top bar / stat tiles / chart area / table), `saas-landing` (logo + nav / headline + CTA / feature grid / 3 icons / footer), and `components` (a framed sheet: primary/secondary/ghost buttons, input + label, card with image/title/price, nav bar, badge/chips, a **code block** with syntax-role bars, a table). **Mia's Step 4 decision: all ten layouts from her reference ship in v0.1.0** — `two-column`, `three-column`, `sidebar`, `blog`, `portfolio`, `documentation` join the five above as data-only template files (11 templates total including `components`).
- Landing and home are the same page (Mia said "choose").

## Solution Architecture

Static React SPA, three hash routes (`HashRouter` — deep links and reloads work on any static host with zero rewrite config, which is the ARCHI §19 deployment contract). Feature folders own their UI; `lib/` holds pure, testable helpers; the wireframe mock is a data-driven spec (template → frames → sections → blocks → color roles); one renderer draws any template, and a template declares one or two frames (e.g. `ecommerce` = web + mobile, `components` = a single sheet).

```
/            Landing = wireframe hero + inline Capture card
/library     Grid + filters + search + export/import
/entry/:id   Detail: images, mock (palette) or frames (design), tags/note editing
```

Color flow: `images[source]` → downsample on Canvas → median-cut quantize (pure function over pixel bytes) → dedupe + luminance sort → `colors: hex[]` → default **role map** (background, surface, text, muted, primary, accent) → wireframe mock reads colors by role. Touchpoint click on a block opens a swatch popover; picking a color rewrites that block's **role** assignment by default (all blocks sharing the role update together), or, via "just this block", writes a per-block override. `roleMap` is entry-wide (one palette, so every template shares the same role colors by design); `blockOverrides` are template-scoped. Both are persisted on the entry so the mock reopens exactly as left.

**Why role-level by default with per-block override:** role-level keeps web and mobile frames in sync from one click and matches how a design system consumes a palette; the per-block escape hatch honors "clicking a block changes its color" literally without making it the only mode. Overrides are keyed by a block's **`overrideKey`** (template-scoped, deliberately shared between a template's web and mobile frames for the same element), so a block overridden on web is overridden on mobile too; each block also has a unique **`renderKey`** for React and accessibility.

**Why `idb` over raw IndexedDB:** promise wrapper, ~1 KB, typed schema; raw IDB event plumbing is the kind of code that hides bugs in tests.

**Why the quantizer is a pure function over `Uint8ClampedArray`:** jsdom has no Canvas. Keeping Canvas only in the downsample step lets the quantizer, dedupe, sort and role assignment be unit-tested with synthetic pixel buffers.

### 4. URL parsing

**File**: `src/lib/url.ts` (new)

- `parsePostUrl(input: string): ParsedPostUrl | null`
- Accept (with or without `www.`, `http(s)`, trailing slash, query/hash): Instagram `/p/<code>`, `/reel/<code>`, `/reels/<code>`, `/<user>/p/<code>`, `/<user>/reel/<code>`; Threads `threads.net/@<user>/post/<code>` and `threads.com/@<user>/post/<code>`.
- Normalization rule (what makes two URLs "the same"): scheme `https`, host without `www.`, path reduced to canonical `instagram.com/p/<code>` (reels normalize to `/p/`? **No** — keep `/reel/` distinct; a reel and a post never share a code) and `threads.net/@<user>/post/<code>`; drop query string and hash.
- Returns `{ platform, normalizedUrl, shortcode, author? }`.
- Fixtures list lives in the test file (TRIP-2 writes it): ≥ 12 valid shapes, ≥ 6 invalid (empty, non-Meta domains, profile URLs, story URLs).

### 5. Persistence

**File**: `src/lib/db.ts` (new)

- `idb` schema `UiRoverDB` v1: store `entries` (keyPath `id`; indexes `by-url` unique, `by-kind`, `by-createdAt`), store `images` (keyPath `id`; index `by-entry`; value `{ id, entryId, order, blob, width, height, mime }`).
- Store `images` value also carries `thumb: Blob` (≤320px longest edge, generated at capture) so the library grid never reads full-resolution blobs.
- API: `createEntry(entry, images[])` — **one readwrite transaction across `entries` + `images`**; if any put fails the whole thing aborts and nothing is orphaned. `deleteEntry(id)` — same, cascades images in one transaction. `updateEntry(id, patch)` — read-modify-write inside one transaction, **serialized per entry** through a small in-module promise queue so two debounced writers (note, role map) never clobber each other with stale full objects. Plus `getEntry`, `listEntries`, `getImageBlob`, `getThumbBlob`, `listImagesForEntry`, `findByUrl`, `importEntries(batch)` (import "merge": one transaction inserting every entry + its images, all-or-nothing), `replaceAll(batch)` (import "replace": one transaction that clears then inserts — old data survives if insert fails).
- Availability guard: `openDb()` catches `SecurityError`/missing `indexedDB` and flips an `inMemory` flag; an in-memory Map-backed fallback implements the same API for the session (ARCHI.md §15). The banner reads from this flag.
- `src/lib/useLibrary.ts` (new): React hook exposing `entries`, `status`, `refresh`, `add`, `update`, `remove`; subscribes via a tiny event emitter in `db.ts` so multiple views stay in sync without a global store.
- `src/lib/useDebouncedPatch.ts` (new): the one place debounced edits live. Holds the pending patch, writes after 300 ms, and **flushes** on field blur, on unmount (route departure), and on `visibilitychange` → `hidden` (the reliable termination signal; `pagehide` as a second trigger). A `beforeunload` handler is registered **only while a patch is dirty** and removed on flush, so the browser's leave-page prompt only appears when there is genuinely unsaved work. Flush kicks off the IndexedDB write immediately; if the page is torn down mid-write the loss is bounded to that one patch. Consumers: note field, tag editor, role map / block overrides.

### 6. Image intake (shared by capture and entry editing)

**File**: `src/features/capture/useImageIntake.ts` (new)

- Sources: `document` `paste` event (`clipboardData.files` / `items` of `image/*`), drop zone (`dataTransfer.files`), hidden `<input type="file" multiple accept="image/*">`.
- Produces `PendingImage[]` (`{ tempId, blob, objectUrl, width, height }`), ordered; supports remove and move up/down (buttons — no drag-reorder in v1).
- Reads dimensions via `createImageBitmap` (fallback `Image`); generates the ≤320px `thumb` Blob on Canvas at the same time. Object URLs are created and revoked inside the same effect (React 19 StrictMode double-invokes effects; a URL created outside the effect gets revoked while still rendered).
- Guards: non-image paste → hint "copy the image, not the link"; >10 images → refuse with message; >12 MB single file → refuse.

### 7. Capture

**Files**: `src/features/capture/CaptureCard.tsx`, `UrlField.tsx`, `ImageTray.tsx`, `KindToggle.tsx` (new)

- `UrlField`: controlled input, live `parsePostUrl`, platform badge (mono "IG" / "TH"), inline error for invalid, **duplicate check** via `findByUrl` → shows "already saved → open" link and **disables Save** (the `by-url` index is unique; there is no silent second copy and no replace-on-capture in v1 — edit the existing entry instead).
- `ImageTray`: thumbnails from `useImageIntake`, source-image radio (palette only), remove/reorder.

### 8. Palette extraction

**Files**: `src/features/palette/downsample.ts`, `quantize.ts`, `roles.ts`, `extract.ts`, `samplePixel.ts`, `containMap.ts` (new)

- `downsample(blob, maxEdge = 160): Promise<Uint8ClampedArray & { width, height }>` — Canvas only here.
- `quantize(pixels, { buckets: 8 }): Rgb[]` — median cut over RGB; skips fully transparent pixels; pure.
- `dedupe(colors, threshold)`: drop colors within a Euclidean RGB distance; `DEDUPE_THRESHOLD = 24` is a named constant, tuned by hand in the browser, and unit tests use colors far outside it so they don't depend on its exact value. `sortByLuminance`.
- `assignRoles(hex[]): RoleMap` — lightest → `background`, second-lightest → `surface`, darkest → `text`, mid-luminance low-sat → `muted`, highest-saturation → `primary`, next → `accent`; fills missing roles by nearest luminance so every role always resolves. 1–2 distinct colors → `RoleMap` still complete (nearest-luminance fill), `degraded: true` so the UI shows the "palette too small" notice; 0 colors is rejected upstream by `extract`.
- `samplePixel(blob, nx, ny): Promise<string>` — pick-from-image. Coordinates are **normalized (0–1) over the intrinsic image**; the caller (`SwatchStrip` sampling mode) converts a click on the displayed `<img>` (`object-fit: contain`) through a **pure** `mapContainClick({ clientX, clientY, rect, intrinsicW, intrinsicH }): { nx, ny } | null` in `src/features/palette/containMap.ts` (returns `null` for clicks in the letterbox), which is unit-tested for portrait-in-landscape and landscape-in-portrait boxes. Decodes via `createImageBitmap`, draws to a 1×1 canvas with a source rect, reads one pixel.
- `extract(blob): Promise<ExtractResult>` where `ExtractResult = { colors: string[]; roleMap: RoleMap; degraded: boolean }` composes the above. **Zero** distinct colors (blank/transparent image) is an extraction **failure** (throws → capture falls back to `design` with the warning), never a degraded success; `degraded` is true for 1–2 colors.
- Fixture images for TRIP-2 tests: synthetic pixel buffers built in-test (solid blocks of known colors), not PNG files, so tests run in jsdom.

### 9. Wireframe mock (Mia's structure)

**Files**: `src/features/palette/mock/spec.ts`, `templates/{ecommerce,classic,dashboard,saasLanding,components,twoColumn,threeColumn,sidebar,blog,portfolio,documentation}.ts`, `WireframeMock.tsx`, `TemplatePicker.tsx`, `Frame.tsx`, `Block.tsx`, `TouchpointPopover.tsx`, `SwatchStrip.tsx` (new)

- `spec.ts` — `MockTemplate = { id, label, frames: FrameSpec[] }`, `FrameSpec = { variant: 'web' | 'mobile' | 'sheet', sections: SectionSpec[] }`, blocks `{ renderKey, overrideKey, role, shape: 'bar' | 'box' | 'pill' | 'text' | 'dot' | 'code', span }`. `renderKey` is unique **per frame** (`ecommerce.mobile.hero.cta`); `overrideKey` is template-scoped (`ecommerce.hero.cta`) and **shared** by the web and mobile versions of the same element, which is how one override reaches both frames. Spec validation: `renderKey` unique within a frame; every `overrideKey` starts with `${template.id}.` and appears in no other template; every block sharing an `overrideKey` must declare the same `role`; roles valid.
  - `code` shape is a **composite**: the block's own `role` (`surface`) paints the container and is its single touchpoint; its line bars use a **fixed internal mapping** (`text` / `accent` / `primary` / `muted`, in a repeating pattern) read from `roleMap` and not individually overridable. Documented in `spec.ts` next to the shape union. Templates in v0.1.0:
  - `ecommerce` (default; Mia's structure) — web + mobile frames: **search bar** · **hero** (visual box, headline bars, primary CTA pill, promo text) · **category row** (5 icon boxes + labels) · **sale banner** (offer text, CTA pill, countdown dots) · **featured products** (3–4 cards: image box, wishlist dot, title bar, price bar, add-to-cart pill) · **social proof** (stars, review bars, trust badges) · **bottom nav** (mobile: 3 icons; web: footer bar).
  - `classic` — web: header · nav · hero · 3-column content boxes · footer.
  - `dashboard` — web: sidebar menu · top bar · 4 stat tiles · chart area (line + bars as shapes) · table rows.
  - `saas-landing` — web: logo + nav links + CTA · headline + sub + CTA · feature grid (2×2) · 3 icon-features · footer.
  - `two-column` — web: header · sidebar + main content · footer. `three-column` — web: header · nav · left sidebar + main + right sidebar · footer. `sidebar` — web: header · nav-list sidebar + main · footer. `blog` — web: header · nav · post list (image + bars) + sidebar · footer. `portfolio` — web: header nav · avatar + intro bars · project grid (3 boxes) · footer. `documentation` — web: docs sidebar list · content with headings + a `code` block · on-this-page column.
  - `components` — one `sheet` frame: button row (primary / secondary / ghost / disabled) · input + label + helper · card (image, title, price, CTA) · nav bar · badge + chips · **code block** (`code` shape: line bars cycling `text` / `accent` / `primary` / `muted` on a `surface` background, mimicking syntax colors) · 3-row table.
- `TemplatePicker.tsx` — segmented control above the mock; selection persisted per entry (`mockTemplate`, default `ecommerce`) via an **immediate** `updateEntry` (a discrete choice, not a debounced edit). Overrides are keyed per template-scoped `overrideKey`, so switching templates keeps each template's overrides.
- `Frame.tsx` — renders a `FrameSpec` as a CSS grid inside a silhouette; `variant` `web` (browser chrome dots), `mobile` (phone silhouette), `sheet` (plain bordered panel). Multi-frame templates sit side by side (stack under 768px).
- `Block.tsx` — a `<button>` keyed by `renderKey`, painted with `blockOverrides[overrideKey] ?? roleMap[role]`; accessible name "`<section> <block>`, `<role>`, `<hex>`" (+ "overridden" when applicable); focus ring; keyboard `Enter`/`Space` opens the popover.
- `TouchpointPopover.tsx` — swatches of the entry's palette + a hex input; two apply modes: **"all `<role>` blocks"** (default, sets `roleMap[block.role]`) and **"just this block"** (sets `blockOverrides[block.overrideKey]`); "clear override" (deletes `blockOverrides[block.overrideKey]`) when one exists; `Esc` closes; focus returns to the block. Built on the shared positioned-div `Popover` (no native `popover` attribute).
- `SwatchStrip.tsx` — the extracted colors, hex labels, click-to-copy, current role chips under each swatch; **remove swatch**, **add by hex**, **pick from image** (enters a sampling mode on the source image; click → `samplePixel` → appended); "reset roles" restores `assignRoles` defaults; "reset palette" re-runs `extract`. Removing a color that a role uses re-assigns that role to the nearest remaining color, and every `blockOverrides` entry holding the removed hex is **deleted** (the block falls back to its role) so no block paints a color outside the palette; **remove is disabled at one swatch** (a palette never reaches zero). Manual edits to `colors` re-evaluate `degraded` (≥3 clears the notice).
- The mock reads from entry state; swatch/role/override edits go through `useDebouncedPatch` → `updateEntry` so `colors`, `roleMap`, `blockOverrides` persist and flush on navigation; `mockTemplate` writes immediately.

### 12. Export / import

**Files**: `src/lib/export.ts`, `src/features/library/ExportImport.tsx` (new)

- Export: `{ format: 'ui_rover', version: 1, exportedAt, entries: [{ ...entry, images: [{ ...meta, dataBase64 }] }] }` → Blob download `ui_rover-YYYY-MM-DD.json`. Thumbs are **not** exported (regenerated on import). Before building the JSON, sum image bytes; above 150 MB show a warning with the size and let Mia proceed or cancel (base64 + string overhead can push a very large library past what a single `JSON.stringify` handles comfortably; a chunked format is a later plan if she ever hits it).
- Import: file input → **validate the complete v1 schema** (`format`, `version`, every `Entry` field with type + enum checks, every image record's `id/order/width/height/mime/dataBase64`, `roleMap` completeness when present, `colors` are hex) — any violation rejects the whole file with the first offending path → **decode every image to a Blob and regenerate thumbs, in memory** → only then write. **Merge by `url`** = one readwrite transaction that inserts every non-colliding entry + its images (`importEntries(batch)`; all-or-nothing, collisions pre-computed and reported as skipped); **replace all** (explicit second confirm) = `replaceAll` in one transaction. A validation, decode, or quota failure therefore never leaves the library half-written or emptied — the result is always "N imported, M skipped" or "nothing changed: <reason>".
- Round-trip test is the contract: export → clear → import → deep-equal entries (minus `id`s if regenerated — decision: keep ids stable on import).

## Technical Considerations

- **Pattern Usage**: feature folders (capture / palette / library), `lib/` for pure helpers, `components/` for shared primitives — per ARCHI.md §4. Shared primitives needed: `Button`, `Badge`, `Field`, `Popover` (used by touchpoints and tag suggestions).
- **Client-only constraint**: no fetch to Instagram/Threads/Meta, no backend, no tokens (ARCHI.md §5.1). This plan adds zero network calls.
- **Data model**: multi-image + `roleMap` + `sourceImageId` supersede ARCHI.md §13; export format v1 is defined here so later migrations have a baseline.
- **Image pipeline**: downsample ≤160px before quantize; Blobs stored, object URLs revoked; main thread. Guard: if `downsample` exceeds ~200 ms on a 12 MB image in manual testing, note it for a Worker follow-up — not in this plan.
- **Styling**: Tailwind v4 utilities + `@theme` tokens; light + dark from day one; chrome stays neutral so palette colors read true against it. The mock's *own* chrome (frame silhouette, labels) uses chrome tokens, never palette colors.
- **Accessibility**: capture flow fully keyboard-operable; every mock block is a real `<button>` with hex in its accessible name; popover traps focus and restores it; swatches announce hex; color is never the only signal (role chips carry text).
- **Edge cases**: unsupported URL, clipboard without image, URL without image (Save disabled, hint), duplicate URL (link to existing, Save disabled), IndexedDB unavailable (in-memory session + banner), extraction failure (save as design + warning), degenerate palette (<3 colors → notice + manual add), image limits (10 per entry, 12 MB each), import of a file that isn't ours (reject with message), import collisions (skip + count), persistence failure mid-save (form state preserved).
- **Performance**: capture-time thumbs (≤320px) for the grid, read on viewport intersection; object URLs created and revoked in the same effect; palettes computed once and stored; debounced patches (300 ms) with flush on blur/leave.

## Type Definitions

```ts
type Platform = 'instagram' | 'threads'
type Kind = 'palette' | 'design'
type Role = 'background' | 'surface' | 'text' | 'muted' | 'primary' | 'accent'
type RoleMap = Record<Role, string>            // hex per role, always complete
type MockTemplateId = 'ecommerce' | 'classic' | 'two-column' | 'three-column' | 'sidebar' | 'dashboard' | 'blog' | 'portfolio' | 'saas-landing' | 'documentation' | 'components'

interface ImageRef { id: string; order: number; width: number; height: number; mime: string }
// `images` store record = ImageRef & { entryId: string; blob: Blob; thumb: Blob }

interface Entry {
  id: string                 // ulid
  url: string                // normalized (lib/url.ts)
  platform: Platform
  author?: string            // from Threads URL / IG user path when present
  shortcode: string
  kind: Kind
  images: ImageRef[]         // ordered; blobs live in the `images` store
  sourceImageId?: string     // which image the palette came from
  colors?: string[]          // hex[], present for palette entries and for designs after "Extract palette"
  roleMap?: RoleMap          // present whenever colors is
  blockOverrides?: Record<string, string>  // overrideKey → hex, per-block touchpoint overrides
  mockTemplate?: MockTemplateId             // last picked template, default 'ecommerce'
  tags: string[]
  note: string
  createdAt: number
  updatedAt: number
}

interface ParsedPostUrl { platform: Platform; normalizedUrl: string; shortcode: string; author?: string }

interface ExportFileV1 {
  format: 'ui_rover'; version: 1; exportedAt: string
  entries: Array<Omit<Entry, 'images'> & { images: Array<ImageRef & { dataBase64: string }> }>
}
```

## Performance & Cost Impact

Bundle: +react-router (~20 KB gz), +idb (~1 KB), +ulid (~1 KB). Extraction on a 160px downsample is sub-50 ms on the main thread. Library grid with a few hundred entries is fine without virtualization; revisit past ~1 000.

## Backward Compatibility

None to preserve (first data-bearing release). This plan *defines* the baseline: IndexedDB schema v1 and export format v1. Future schema changes go through `idb`'s `upgrade` callback and bump both versions together.
