# Read the Palette — OCR, Crop, Swatch-Blob Fallback Implementation Plan

## Overview

v0.1.0 extracts a palette by quantizing the whole screenshot. Real palette posts are cards: a handful of swatches plus printed hex codes, surrounded by Instagram/browser chrome — so quantize returns chrome grays. v0.2.0 makes ui_rover **read the card**: OCR the printed hex codes (client-side Tesseract.js, assets bundled, lazy-loaded), let Mia **crop** the source image to the card, and when a post prints no hex text, detect the **swatch blobs** (large uniform-color regions) instead. Quantize remains the last-resort fallback. Runs automatically on save and on demand from the entry page, always with a **preview + review-and-adjust** step: on save the result is applied and reviewed on the entry page; on the entry page the result is previewed and applied only on Apply.

## Problem Statement

Observed 2026-09-16 on a real entry (dopely.colors "Calm SaaS", full-window screenshot): extraction produced `#e8ecef #c7d7fe #757a8a #484340 #283e43 #15181c` (Chrome + Instagram chrome) while the card printed `#101828 #2F6BFF #475467 #D0D5DD #FFFFFF` (the blue was verified as `#2F6BFF` at 10× zoom during the spike). The pipeline had no notion of *where* the palette is or that it is *written down*.

## Discovery decisions (Step 1, 2026-09-16)

- **Trigger:** auto on save (OCR → swatch blobs → quantize, with progress shown) **and** a "Read palette again" control on the entry page, where crop lives.
- **OCR assets bundled locally**, never fetched from a CDN — keeps ARCHI §5.1/§18 (no remote requests) intact. Assets are copied from `node_modules` into `public/ocr/` by a script at `predev`/`prebuild`; the folder is gitignored, so the repo stays small and the built `dist/` is self-contained (~6 MB more, loaded only when a read runs).
- **Confirm step:** results appear as a preview list with checkboxes; **Apply replaces** the palette by default (roles re-assigned, block overrides cleared); an **Append** action adds the checked colors to the existing swatches only (roles and overrides untouched — Append never removes anything, so it cannot move a role).
- **On save, the read result is applied immediately** (the entry always lands with a palette) and the entry page opens the review panel pre-filled, so the "confirm" on save is really a *review-and-adjust* step (uncheck a misread → Apply, or dismiss). The alternative — a confirm dialog inside Capture before the entry is created — makes Save two clicks. **Mia's Step 4 decision (2026-09-16): apply-then-review.**
- **No new storage surfaces:** Tesseract.js is configured with `cacheMethod: 'none'` so it does not create its own IndexedDB cache for language data (assets are same-origin and small enough to re-fetch per session); the app's `ui-rover` database stays the only persistent store (ARCHI §13/§18).
- Inherited from v0.1.0 and unchanged: no Meta API; one persistence owner per field group (`MockPanel` owns palette fields); screenshot is the source of truth.

## Solution Architecture

A new `features/palette/read/` module with three pure-ish detectors behind one orchestrator, plus two UI pieces (crop tool, read panel) owned by `MockPanel`.

```
readPalette(blob, { sourceImageId, crop?, onProgress?, signal? })
  ├─ blobs = detectSwatchBlobs(downsample ≤240px)   pure — also yields the auto-crop (non-edge blob ≥ 1.5 % containing the most small blobs, unpadded)
  ├─ cropToBlob(blob, crop ?? autoCrop)   Canvas: sub-rect passes — card @1200px + right 45 % column @1000px, unioned, early stop at 5
  ├─ ocrHexCodes(blob)                 Tesseract.js worker (lazy singleton) → tokens → strict hex parse + conservative repair
  │     ≥ 3 hexes → { source: 'ocr' }
  ├─ detectSwatchBlobs(pixels)         pure: downsample ≤240px → 4-bit color bins → connected components → area-ranked
  │     ≥ 3 blobs → { source: 'blobs' }
  └─ quantize pipeline (existing extract)  → { source: 'quantize' }
→ ReadResult { colors, roleMap, source, candidates[], degraded }
```

**Spike result (2026-09-16, `docs/6-memo/ocr-spike.md`): PASS** — `OEM.LSTM_ONLY` · `PSM.AUTO` · whitelist **off** · crop + smooth upscale to **1200 px** wide = 4/5 exact, 0 false positives, ~235 ms warm; a two-pass union (1200 + 1900 px) = 5/5 in Node. **Superseded by the browser follow-up (same memo):** in the shipping runtime the 1900 px pass never helped; the right 45 % column of the unpadded card bbox at 1000 px reads 4/5 across PSM 3/4/6, unioned with the card pass; `#d0d5dd` surfaces only as a repaired candidate. `SPARSE_TEXT` scored 0/5 everywhere, the whitelist only manufactured false positives, legacy lost outright (not bundled). **Full-image OCR scored 0/5 with 6 false positives** — OCR is only useful on the card, so save-time reads derive an **auto-crop** from the swatch-blob detector (largest non-edge blob ≥ 5 % of the image, padded 2 %) before OCR, and the orchestrator applies the two-pass union whenever pass 1 reads < 3 codes. `ReadResult.autoCrop` reports the rect used so the UI can show it and offer to keep it.

**Spike before Phase 1 (~30 min, gating) — as originally scoped:** run Tesseract.js v7 on the dopely fixture (cropped and uncropped) with and without `tessedit_char_whitelist`, LSTM-only vs `legacyCore`/`legacyLang`. The whitelist is a Legacy-engine variable; under `OEM.LSTM_ONLY` it may be inert, and forcing hex characters over a whole card can turn ordinary labels into hex-shaped garbage. The spike decides: (a) whitelist on/off, (b) whether the legacy core + language (≈ +10 MB) are worth bundling, (c) PSM (`SPARSE_TEXT` vs `AUTO`). For the legacy arm, the spike temporarily copies the legacy core builds (`tesseract-core.wasm.js`, `tesseract-core-simd.wasm.js`, `tesseract-core-relaxedsimd.wasm.js`) and `@tesseract.js-data/eng/4.0.0/eng.traineddata.gz` into `public/ocr-spike/` (gitignored, deleted after the spike; never part of the shipped asset script unless the spike picks legacy, in which case `copy-ocr-assets.mjs` is extended and the size estimate restated). Its result is recorded at the top of `ocrConfig.ts`. If neither configuration reads ≥ 4 of the 5 dopely codes, the plan is re-scoped before any UI work.

**Why OCR first:** printed hex codes are exact; every other method guesses. **Why blobs second:** posts that draw swatches without text still have large flat regions; a uniform-region detector finds them where median-cut smears them with the background. **Why quantize last:** it is never wrong about *something* being there, so the UI always has a palette to show.

**Why a review step even on save:** OCR misreads (`0`/`O`, `8`/`B`) are plausible-looking; a wrong hex silently replacing a palette is worse than a 1-click review. On save the result is applied and the review opens on the entry page right after navigation (router-state `pendingRead`), so save stays one click and the adjustment happens where the mock is.

**Why the worker is a lazy singleton with idle teardown:** creating a Tesseract worker costs ~1 s and ~50 MB; reading five entries in a row should pay that once. Terminate after 60 s idle so a long library session doesn't hold the memory.

**Why crop is stored on the entry:** re-running the read after a misfire must reuse the same rectangle; a crop is per source image and normalized (0–1) so it survives display-size changes.

Add `@tesseract.js-data/eng@^1` as a dependency. The script `process.exit(1)`s with the missing path if any source is absent, is idempotent, and prints what it copied.
- Scripts: `"predev": "node scripts/copy-ocr-assets.mjs"`, `"prebuild": "node scripts/copy-ocr-assets.mjs"`. Vitest never needs the assets (OCR is mocked).
- `.gitignore`: add `public/ocr/` and `public/ocr-spike/`.

**File**: `vite.config.ts` — nothing required for `public/` assets; confirm `worker.min.js` is served with the correct MIME in dev (Vite serves `public/` verbatim).

**File**: `src/features/palette/read/ocrConfig.ts` (new) — the three asset paths (`workerPath`, `corePath`, `langPath`) as **absolute URLs**: `new URL(`${import.meta.env.BASE_URL}ocr/`, location.href).href` (tesseract.js spawns the worker from a `blob:` URL by default, so a relative path would resolve against the blob URL and break); `corePath` points at the `ocr/` directory so `getCore` can pick the right wasm variant. `cacheMethod: 'none'`. Language `eng`, `OEM.LSTM_ONLY`. PSM and `tessedit_char_whitelist` are set **from the spike's result** (default hypothesis: `SPARSE_TEXT`, whitelist off, `#` required for bare tokens — see §3). Unit test: the path builder yields same-origin absolute URLs under `BASE_URL` `/` and `/ui_rover/`.

### 2. Crop math and crop-to-blob

**Files**: `src/features/palette/read/cropRect.ts` (pure, new), `src/features/palette/read/cropToBlob.ts` (Canvas, new)

- `NormalizedRect { x, y, w, h }` in 0–1 over the intrinsic image; `clampRect`, `rectFromPoints(p1, p2)`, `nudgeRect(rect, dx, dy)` (keyboard), `MIN_CROP_EDGE = 0.05`.
- `cropToBlob(blob, rect, { minWidth = 1200 })` → `Blob` (PNG): draws the sub-rectangle to a canvas scaled up so the crop is at least `minWidth` px wide with `imageSmoothingEnabled = true` and `imageSmoothingQuality = 'high'` (nearest-neighbour adds no detail and blocks glyph edges; the spike A/Bs this on the fixture). OCR runs on this blob; quantize/blobs also run on it when a crop exists. Upscaling matters: hex codes on a 1080px IG card are ~10 px tall, below Tesseract's sweet spot (~20–30 px x-height).
- Reuses `mapContainClick` (`containMap.ts`) to turn pointer events on the displayed `<img>` into normalized coordinates — no new coordinate code.

### 3. OCR hex reader

**Files**: `src/features/palette/read/ocrWorker.ts` (new), `src/features/palette/read/hexTokens.ts` (pure, new), `src/features/palette/read/ocrHexCodes.ts` (new)

- `ocrWorker.ts` — lazy singleton: `getWorker()` creates the Tesseract worker with `ocrConfig` on first call (`createWorker('eng', OEM.LSTM_ONLY, { workerPath, corePath, langPath, cacheMethod: 'none', logger })`) and memoizes the promise; `releaseWorkerSoon()` schedules `terminate()` after 60 s idle, cancelled by the next `getWorker()`. After creation, `getWorker()` applies the spike-selected parameters once via `worker.setParameters({ tessedit_pageseg_mode, tessedit_char_whitelist })` (values from `ocrConfig.ts`; an empty whitelist means "off"). `recognizeHexText(blob, onProgress)` then runs `worker.recognize(blob, {}, { blocks: true })` — v7 returns only `text` unless the output option asks for `blocks` — and flattens `blocks → paragraphs → lines → words` into the raw `words[]` (text + confidence + bbox). Progress callback maps Tesseract's `logger` statuses to three UI states: `loading-engine`, `recognizing` (with 0–1 progress), `done`.
- `hexTokens.ts` — pure. `parseHexTokens(words, blobs?): HexCandidate[]`: strict match `^#[0-9a-f]{6}$` (case-insensitive) on each word; a **bare** 6-hex token (no `#`, e.g. `101828`) is accepted only when its bbox sits within one line-height of a detected swatch blob's bbox (`blobs` from §4, passed in by the orchestrator) — otherwise a random number on the page would read as a color, plus a **conservative repair** only for tokens that *start with* `#` and have ≤ 2 ambiguous characters: `O→0`, `o→0`, `I/l/|→1`, `S→5`, `Z→2`, `B→8` (only when the resulting token is valid hex); repaired candidates carry `repaired: true` and lower confidence so the preview shows them last and unchecked. Dedupe case-insensitively, keep reading order (top-to-bottom, left-to-right by bbox), cap at 12. Also accept 3-digit shorthand `#abc` → expanded, flagged `repaired`.
- `ocrHexCodes(blob, { blobs?, onProgress?, signal? }): Promise<HexCandidate[]>` composes the two (`blobs` feed the bare-token proximity rule in `parseHexTokens`) and never throws for "no text" — returns `[]`; throws `OcrUnavailableError` only if the engine cannot load (assets missing) so the orchestrator falls through to the next detector and the UI can say "OCR unavailable" instead of failing the read.

### 4. Swatch-blob detector

**File**: `src/features/palette/read/swatchBlobs.ts` (pure, new)

- `detectSwatchBlobs(pixels: Uint8ClampedArray, width, height, { minAreaFraction = 0.004, maxBlobs = 8 }): BlobCandidate[]`.
- Quantize each pixel to a 4-bit-per-channel bin (4096 bins) so anti-aliased edges don't split a swatch; 4-connected component labeling (two-pass union-find over the ≤240px buffer — cheap); per component: area, bbox, mean color (full precision, not the bin), aspect ratio, `touchesBorder`.
- Filter: area ≥ `minAreaFraction` of the image; aspect ratio between 1:4 and 4:1 (swatches are circles/squares/short bars, not rules or borders); drop **every** component that touches ≥ 2 image edges **and** exceeds `BACKGROUND_AREA_FRACTION` (15 % of the image) — that removes the page background *and* browser/app chrome bands, while a full-bleed swatch smaller than the cap survives; drop components whose mean color is within `DEDUPE_THRESHOLD` of an already-kept blob.
- Rank by area descending; return mean colors as hex with `area` and `bbox` for the preview.
- Reuses `downsample` for the input buffer (≤240px here, a separate `maxEdge` argument — larger than quantize's 160 because blobs need shape fidelity).

### 5. Orchestrator

**File**: `src/features/palette/read/readPalette.ts` (new)

- `readPalette(blob, { sourceImageId, crop?, onProgress?, signal? }): Promise<ReadResult>`; `ReadResult = { colors: string[]; roleMap: RoleMap; degraded: boolean; source: PaletteSource; candidates: ReadCandidate[]; autoCrop?: NormalizedRect; ocrUnavailable?: boolean }` where `ReadCandidate = { hex, source, confidence?, repaired?, area? }`.
- Steps: (0) the orchestrator **ignores `crop` when `crop.imageId !== sourceImageId`** (that is how a stale rect from a previous source image is neutralised without relying on every writer to clear it — nobody clears it; the next crop overwrites it); (1) `input = crop ? await cropToBlob(blob, crop) : blob`; (2) `blobs = detectSwatchBlobs(downsample(input, 240))` (cheap, always computed — it feeds the bare-token proximity rule **and** the auto-crop: when no usable `crop` was given, the largest blob that touches no image edge and covers ≥ 5 % of the image, padded 2 % and clamped, becomes `autoCrop`); (3) `ocr = await ocrHexCodes(cropToBlob(input, crop ?? autoCrop, 1200), { blobs, onProgress, signal })`, as two sub-rect passes — card @1200 px, then the right 45 % column @1000 px — unioned with early stop at 5 unrepaired codes (`OCR_PASSES` in `ocrConfig.ts`); with neither crop nor auto-crop, OCR is **skipped** (full-image OCR measured 0/5 with false positives) — catch `OcrUnavailableError` → `ocrUnavailable: true`, continue; if `ocr.length ≥ 3` → source `'ocr'`, colors = unrepaired first, then repaired; (4) else if `blobs.length ≥ 3` → `'blobs'`; (5) else `extract(input)` (existing) → `'quantize'`, or rethrow `ExtractionError`. `roleMap = assignRoles(colors)`, `degraded = degradedFor(colors)`. Candidates from *all* detectors that ran are returned so the preview can offer the OCR misses alongside blob colors (checked by default only for the winning source).
- `PaletteSource = 'ocr' | 'blobs' | 'quantize'` — recorded on the entry for the review summary and future debugging; hand edits leave it as-is (no "manual" state, no badge — not asked for).
- **Every extraction path routes through `readPalette`:** `CaptureCard` save, `MockPanel.handleExtractSelected` (re-extract), `MockPanel` reset palette, and `EntryPage.handleExtract` (first extract on a design entry — `MockPanel` is not mounted yet at that moment, so `EntryPage` runs the read with progress/cancel UI on its own button, applies the result through `updateEntry` exactly as today, and then passes the `ReadResult` to the now-mounted `MockPanel` as a `pendingRead` **prop from local state** so the review panel opens; same hand-off Capture makes via router state, minus the router). `extract()` remains as the quantize step only.

### 6. Data model & persistence

Export format stays **v1**: both fields are optional and `validateEntry` already ignores unknown keys, so old files import unchanged and new files are still v1.

**File**: `src/lib/db.ts` — no schema change (IndexedDB stores whole `Entry` objects; new optional fields need no index). No version bump.

**File**: `src/lib/export.ts` (modify) — version unchanged; `validateExportFile` validates the two optional fields **when present** (`paletteSource` in the enum; `crop` rect within 0–1 with `w`/`h` ≥ `MIN_CROP_EDGE`, `imageId` present in that entry's images) and reports the offending path as today.

### 7. Capture: read on save

**File**: `src/features/capture/CaptureCard.tsx` (modify)

- Replace the `extract(sourceBlob)` call with `readPalette(sourceBlob, { sourceImageId: records[sourceIdx].id, onProgress, signal: controller.signal })` where `controller` is a `ReadController` created per save attempt (its `cancel()` backs the `Cancel read` button). The Save button shows the progress state ("Loading reader…", "Reading… 40%") and stays `aria-busy`. `ExtractionError` handling unchanged (design + notice).
- The entry is created with the read's `colors`/`roleMap`/`paletteSource` **applied** (so a reload shows a palette), and navigation carries `state: { pendingRead: ReadResult, focusHeading: true }`; `EntryPage` reads `pendingRead` **once on mount, then immediately replaces the history entry with `state: null`** (same pattern as the existing `notice`), so Back/reload can never re-offer a stale result whose Apply would overwrite later edits; it hands the result to `MockPanel`, which opens the **Read panel in review mode** with the candidates pre-checked, so Mia can uncheck a misread and Apply, or dismiss to keep what was applied. (Keeping the result applied *and* offering the review avoids a "palette-less" entry if she navigates away.)
- Timing guard: OCR engine load on the very first save can take 1–3 s; the save button text makes that visible, and a `Cancel read` control aborts the read. **Cancellation policy is per caller:** the orchestrator rejects with a distinct `ReadCancelledError` (defined in `readProgress.ts`); **Capture** catches it and falls back to the plain quantize `extract()` so the entry is still created with a palette; the **entry page** (`MockPanel` / `EntryPage`) catches it and leaves the palette exactly as it was (nothing queued, nothing written). Cancelling terminates the worker singleton (it re-creates lazily on the next read).

### 8. Entry page: crop tool and read panel

**Files**: `src/features/palette/read/CropTool.tsx`, `ReadPalettePanel.tsx` (new); `src/features/palette/mock/MockPanel.tsx` (modify); `src/features/palette/mock/SwatchStrip.tsx` (modify)

- **Where the controls live:** `ReadPalettePanel` and `CropTool` render inside `MockPanel`, i.e. once an entry has a palette. A design entry without a palette shows only the existing "Extract palette" button on `EntryPage` (now backed by `readPalette` + progress + cancel); its result mounts `MockPanel` with the review open. No crop-before-first-read on design entries in v0.2.0 — crop is set on the entry page and used by re-reads.
- `CropTool` — overlays the source `<img>` (object-fit contain); pointer drag draws a rectangle (via `mapContainClick` for both corners), shown as a dimmed mask outside + `wire` outline; handles: drag inside to move, corner drag to resize; keyboard: arrows nudge 1 % (Shift = 5 %), `Enter` confirms, `Esc` cancels; "Clear crop". Emits `NormalizedRect | null`. Accessible name and live region announcing the rect in percentages.
- **Divergence recorded at release (2026-09-16):** the planned "crop first, with Skip crop" flow was **not** built. The auto-crop (spike follow-up) finds the card without user input, so "Read palette" reads immediately and a separate **Crop** button opens the tool only when Mia wants to override; the review panel offers "Keep this crop" for auto-crops. Crop-first would have added a click to every read for no measured gain.
- `ReadPalettePanel` — the control surface (when a read used an `autoCrop`, the panel shows "Read from the detected card" with a "Keep this crop" action that stores it as the entry's `crop`): "Read palette" button (reads immediately — see the divergence above; a separate Crop button opens the tool), progress states, then the **preview**: candidate rows (swatch, hex, source badge `OCR` / `BLOB` / `QUANT`, confidence, "repaired" marker), checkboxes (winning source checked by default), **Apply (replace)** and **Append**, Cancel. A one-line summary "Read 5 hex codes from the crop" / "No hex text found — using swatch shapes" / "OCR unavailable — using swatch shapes".
- `MockPanel` — remains the single owner: `applyRead(result, mode)` goes through the existing `extractInto` path (await the read → `discard()` → set draft → queue `{ colors, roleMap, blockOverrides: {}, paletteSource, crop }` → flush). Append mode: `colors = dedupe([...draft.colors, ...checked])` — swatches only; `roleMap` and `blockOverrides` are untouched (the panel says "adds swatches, keeps roles"). `crop` is written by the crop tool through the same owner (immediate write like `mockTemplate`, with revert + retry). Reset palette now calls `readPalette` (with the stored crop) instead of `extract`.
- `SwatchStrip` — unchanged except that "Reset palette" now triggers `readPalette` through `MockPanel`.

## Technical Considerations

- **Pattern Usage**: new `features/palette/read/` folder alongside `mock/`; pure helpers (`hexTokens`, `swatchBlobs`, `cropRect`) separated from Canvas/worker-bound ones (`cropToBlob`, `ocrWorker`) exactly like `quantize` vs `downsample` today.
- **Client-only constraint**: Tesseract runs in a Web Worker in the browser with bundled assets; **no network request at any point** (verify in the manual check with DevTools Network filtered to `ocr/` — all requests same-origin).
- **Data model**: two optional `Entry` fields; export format stays v1 (optional fields validated when present); IndexedDB untouched.
- **Image pipeline**: crop → upscale for OCR only; blobs on ≤240px; quantize unchanged at 160px. Main thread for crop/blobs (tens of ms); OCR is already off-thread.
- **Styling**: crop mask + outline from chrome tokens; source badges reuse `Badge`; preview rows reuse swatch styling.
- **Accessibility**: crop tool fully keyboard-operable with a live region; preview rows are labelled checkboxes; progress announced via `aria-live="polite"`; Apply/Append/Cancel are real buttons; focus returns to "Read palette" after the panel closes.
- **Edge cases**: OCR assets missing (dev without `predev`) → `OcrUnavailableError` → blobs/quantize + "OCR unavailable" note (never a blank palette); zero hex + zero blobs + quantize failure → existing `ExtractionError` path; hex codes without `#` (many posts print `101828`) → accepted by the strict regex; 3-digit hex; duplicated codes on multi-slide carousels; crop smaller than 5 % → rejected with a hint; source image changed → the stored crop is ignored (imageId mismatch) until a new crop is drawn; read cancelled mid-way → nothing written; worker crash → treated as unavailable for this read, singleton reset.
- **Performance**: worker singleton + 60 s idle teardown; crop upscale capped at 2000px wide; full-image OCR (no crop) is downscaled to ≤2000px longest edge first; blob labeling on ≤240px (≤57 600 px) is < 20 ms.

## Type Definitions

```ts
type PaletteSource = 'ocr' | 'blobs' | 'quantize'
interface NormalizedRect { x: number; y: number; w: number; h: number }   // 0–1 over the intrinsic image
interface HexCandidate { hex: string; confidence: number; repaired: boolean; bbox?: { x0; y0; x1; y1 } }
interface BlobCandidate { hex: string; area: number; bbox: { x0; y0; x1; y1 } }
type ReadCandidate = { hex: string; source: PaletteSource; confidence?: number; repaired?: boolean; area?: number }
interface ReadResult { colors: string[]; roleMap: RoleMap; degraded: boolean; source: PaletteSource; candidates: ReadCandidate[]; autoCrop?: NormalizedRect; ocrUnavailable?: boolean }
interface Entry { /* v0.1.0 fields… */ paletteSource?: PaletteSource; crop?: { imageId: string } & NormalizedRect }
```

## Performance & Cost Impact

`dist/` grows **≈ 15 MB** on disk (`public/ocr/`: worker ≈ 0.1 MB, three lstm core builds ≈ 3.9 MB each, `eng.traineddata.gz` ≈ 2.95 MB) — but a browser fetches **one** core build (≈ 3.9 MB) plus the language data (≈ 3 MB) ≈ 7 MB, same-origin, only on the first read of a session (`cacheMethod: 'none'`, so the HTTP cache is the only cache). If the spike picks the legacy engine, add ≈ 10 MB of legacy language data and restate this. First read: ~1–3 s engine load + 1–4 s recognition on a cropped card; subsequent reads: recognition only. Memory ~50 MB while the worker lives (60 s idle teardown). Main bundle unchanged (Tesseract's JS entry is small; the heavy parts are the assets).

## Backward Compatibility

Entries without `paletteSource`/`crop` behave exactly as before (`paletteSource` displayed as "quantize" when absent and colors exist). Export format stays v1 with two optional fields; a v0.1.0 app importing a v0.2.0 file simply ignores them. IndexedDB schema unchanged.
