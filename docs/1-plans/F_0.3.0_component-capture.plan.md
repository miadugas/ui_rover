# Component Capture (+ optional URL) Implementation Plan

## Overview

v0.3.0 makes design posts *extractable*: on a design entry, Mia draws a rectangle over a screenshot (the v0.2.0 `CropTool`), tags it (button, nav, card, …), and it becomes a **component entry** — its own library card with a cropped image, thumb, fixed + free tags, a note, a link back to the parent post, and the same optional palette read as any design. Components show in the library (new `component` kind filter + component-tag filter) and in a Components strip on the parent page. Because component entries have no post URL, this release also makes the **post URL optional** everywhere (the queued v0.2.1), so a screenshot alone can be captured.

## Problem Statement

Mia's original ask: UI/UX posts should be "extracted and mocked up for later reference as a library of frontend things I like". v0.1.0 stored designs only as framed screenshots; the actual things she likes — a button, a nav, a card — are buried inside those screenshots and can't be found or compared later. Separately, `Entry.url` is required and unique, which blocks both URL-less captures and any second entry derived from the same post.

## Discovery decisions (Step 1, 2026-09-16)

- **Model:** components are **own entries** (`kind: 'component'`) with `parentId` + `sourceImageId` + `sourceRect`, their own cropped image + thumb, no URL. → the URL-optional change is folded into this plan.
- **Tags:** fixed **component chips** (`button, nav, card, form, input, list, modal, table, hero, footer, typography, icon, chart, other`) **plus** the existing free-form `TagEditor`.
- **Surfaces:** library cards (kind filter `component`, component-tag filter) **and** a Components strip on the parent design page.
- Inherited: no Meta API; single persistence owner per field group; screenshot is the source of truth; measured OCR config untouched.

## Solution Architecture

```
Design entry page ──"Capture component"──▶ CropTool (on the selected image)
        ▼ confirm
   ComponentForm (chips + free tags + note)
        ▼ save
   cropComponent(parentBlob, rect)  → WebP/JPEG blob at natural size + makeThumb → ImageRecord
   createEntry({ kind:'component', parentId, parentImageId, sourceRect, sourceImageId: ref.id, componentTags, tags, note, images:[ref] }, [record])   — one transaction
        ▼
   Components strip on the parent  ·  Library card  ·  Component entry page (image, parent link, tags, note, Extract palette)
```

**Why own entries, not nested:** every existing surface (grid, filters, thumbs on intersection, export/import, palette read, delete) works on `Entry`; nesting would re-implement each with a special case. The price is two integrity rules — a parent index for cascade delete and import-time parent presence — both small.

**Why the crop is materialized as its own image:** thumbs, the library grid, export, and the palette read all consume `images[]` records. Storing only a rect would force every consumer to re-crop the parent on the fly and would break if the parent image is later removed.

**Why URL becomes optional now:** the `by-url` unique index forbids a second entry with the parent's URL, and components have no URL of their own. IndexedDB does not index records whose key-path value is `undefined`, so `url?` costs no schema change; identity is already the `ulid` id.

## Implementation Details

### 1. Types

**File**: `src/types.ts` (modify)

- `Kind = 'palette' | 'design' | 'component'`; `type CaptureKind = Exclude<Kind, 'component'>` for `KindToggle` and `CaptureCard` state — capture never creates components (they only come from a parent), and the narrower type makes that a compile error.
- `Entry.url?: string`, `Entry.platform?: Platform`, `Entry.shortcode?: string` (all optional; absent together when captured without a URL or for components).
- New optional component fields: `parentId?: string`, `parentImageId?: string` (the parent image the rect was drawn on), `sourceRect?: NormalizedRect` (that rect, normalized over the parent image), `componentTags?: ComponentTag[]`. **`sourceImageId` keeps its existing meaning — an image in *this* entry's `images[]`** (for a component: its own cropped image). `EntryPage`, `MockPanel` and `readPalette` read and *write* `sourceImageId` for the entry's own palette source; overloading it would let the first Extract palette overwrite the parent pointer and orphan `sourceRect`.
- `ComponentTag` union + `COMPONENT_TAGS` const array (the 14 chips) as the only new runtime export.

### 2. Persistence

**File**: `src/lib/db.ts` (modify)

- **Schema v2**: `DATABASE_VERSION = 2`; `upgrade(db, oldVersion)` becomes version-aware: store + index creation for v1 runs only when `oldVersion < 1`, and `by-parent` (non-unique, on `entries.parentId`) is added when `oldVersion < 2`. Today's `upgrade` creates both stores unconditionally — at `oldVersion === 1` that throws `ConstraintError`, and `openIndexedDb`'s catch-all would silently flip to in-memory (an empty library). §15 records that failure mode; the upgrade test covers it. `by-url` stays unique — URL-less records are simply not indexed.
- `deleteEntry(id)` cascades **one level** (a component can never be a parent — `createEntry` rejects `parentId` pointing at a component): in the same transaction, `index('by-parent').getAllKeys(id)` → for each child delete its images (`by-entry`) and the child, then the parent's images and the parent. Same pattern as today's image delete (keys first, then deletes — no mutating cursor). In-memory fallback mirrors it.
- `listChildren(parentId)` (ordered by `createdAt`), used by the Components strip.
- `findByUrl` unchanged; callers only call it when a URL exists.
- **In-memory fallback parity:** `addToMemoryMaps` and `performUpdate` currently treat `entry.url === next.url` as a collision — with two URL-less entries that is `undefined === undefined`. Both checks skip when `next.url` is absent, mirroring the index behavior.
- `createEntry` validation: a `component` must have `parentId` present in the store (checked inside the transaction) and exactly one image; a non-component must not have `parentId`.

### 3. Export / import

**File**: `src/lib/export.ts` (modify) — format stays **v1**:

- `validateEntry`: `url`/`platform`/`shortcode` optional (validated when present, all-or-none); `kind` accepts `component`; when `kind === 'component'`: `parentId` string, `parentImageId` string, `sourceRect` valid rect, `componentTags` ⊆ `COMPONENT_TAGS`, exactly one image, and `sourceImageId` equal to that image's id. Cross-entry checks run in resolution pass 2 (see below): the resolved parent must be a non-component and `parentImageId` must be one of the parent's `images[].id` — otherwise the component is orphaned (skipped + counted), never written.
- Import resolution runs in two passes **before any write**: (1) resolve collisions — Merge skips entries colliding by `id`, or by `url` when they have one; Replace accepts everything in the file (the database is cleared first); (2) validate components against **the set of parent ids that will exist after the operation** — for Merge: existing database ids ∪ accepted file parents; for Replace: accepted file parents only (a pre-existing parent does not survive the clear). A component whose parent is not in that set is **skipped as orphaned** and counted separately. Writes are parent-first within one transaction (`writeBatch` sorts non-components before components for both `importEntries` and `replaceAll`); import bypasses `createEntry`'s per-call parent check because presence was proven in pass 2. Both Merge and Replace return the same structured outcome `{ imported, skipped, orphaned }`, rendered by `ExportImport.tsx` as "N imported, M skipped, K orphaned components" (Replace today hardcodes its result line — it switches to the structured outcome).
- Export unchanged apart from carrying the new optional fields.

### 4. URL optional in capture

**Files**: `src/features/capture/UrlField.tsx`, `CaptureCard.tsx` (modify)

- Label "Post URL (optional)"; empty is valid; invalid non-empty still errors; duplicate check only when parsed.
- Save enabled with ≥1 image regardless of URL. Entry built without `url/platform/shortcode/author` when empty.
- `EntryPage` header: platform badge + "Open original post" only when `url` exists; **one** fallback title, `entryTitle(entry, parent?)` in `lib/platform.ts` → `shortcode` when present, else "Untitled capture"; for components the caller passes the resolved parent and gets "Component of <parent title>" (or "Component" when the parent can't be resolved). `LibraryPage` builds a `parentsById` map from its loaded entries once and hands each component card its parent; `EntryPage` loads the parent with `getEntry(parentId)`. Used by the `<h1>`, image `alt`, cards, the Recent row and the strip label; `EntryCard`/`LandingPage` recent row: platform badge optional. `FilterBar` platform chips: an entry with no platform matches only "All".

### 5. Component capture on the parent page

**Files**: `src/features/components/` (new folder): `ComponentCapture.tsx`, `ComponentForm.tsx`, `ComponentStrip.tsx`, `componentTags.ts` (labels), `cropComponent.ts` (new); `src/app/EntryPage.tsx` (modify)

- `EntryPage` (design entries): "Capture component" button next to the carousel → `ComponentCapture` overlays the **selected** image with `CropTool` (existing props; the rect is **local component state**, `onChange` only updates that state and `onConfirm` hands it to the form — it never touches the parent entry's palette `crop`, which `MockPanel` owns) → on confirm shows `ComponentForm` (chip toggles from `COMPONENT_TAGS`, free `TagEditor`, `NoteField`, Save / Back to crop / Cancel).
- `cropComponent(parentBlob, rect)` is its own small Canvas-bound helper (not `cropToBlob`, which is tuned for OCR and always emits PNG): decode the parent, draw the sub-rectangle at **natural pixel size**, encode with the same `thumbMimeType()` detection as `makeThumb` (WebP, else JPEG) at quality 0.92 — a PNG re-encode of a JPEG-sourced region can exceed the parent's size — then `makeThumb` for the grid. If the encoded crop still exceeds `MAX_IMAGE_BYTES` (12 MB, only plausible for near-full-image rects on huge sources) the capture is rejected with an inline "Crop is too large — draw a smaller area" error; nothing is written. Save → `createEntry(componentEntry, [record])` with `sourceImageId` = the new crop's own image id and `parentImageId` = the parent image the rect was drawn on; on success the strip refreshes via the change emitter and focus moves to the new strip item; on failure the form stays with an inline error.
- `ComponentStrip` on the parent page: thumbs (via `useThumbUrl`), chip tags, link to `/entry/:id`, remove (confirm → `deleteEntry`). Hidden when the entry has no children.
- Component entry page (same `EntryPage`, `kind === 'component'`): cropped image at natural size (max height like the carousel), "From: <parent shortcode or 'Untitled post'>" link with the parent's thumb, component chips (editable — **written by `EntryPage`'s existing `useDebouncedPatch` instance**, the same owner as `tags`/`note`, ARCHI §5.7), `TagEditor`, `NoteField`, delete, and the existing design-style "Extract palette" → `readPalette` on the component image (no crop; auto-crop applies) → `MockPanel`.

### 6. Library

**Files**: `src/features/library/filters.ts`, `FilterBar.tsx`, `EntryCard.tsx`, `EmptyState.tsx` (modify)

- `KindFilter` gains `component`; `componentTag: ComponentTag | 'all'` filter; chips only rendered when at least one component exists.
- `EntryCard` for components: cropped thumb, `COMPONENT` badge, component chips (max 3), parent shortcode as a muted line; no platform badge when absent.
- Text search includes `componentTags`.

## Technical Considerations

- **Pattern Usage**: new `features/components/` folder; pure helpers (`componentTags.ts`, validators) vs Canvas-bound `cropComponent.ts`; primitives reused (`Button`, `Badge`, `Field`, `Popover`, `CropTool`, `TagEditor`, `NoteField`).
- **Client-only**: unchanged; no network.
- **Data model**: schema **v2** (index only) with an `upgrade` path; export format v1 with optional fields; import must order parents first and skip orphans.
- **Image pipeline**: component crop at natural resolution via its own `cropComponent` helper (WebP/JPEG like thumbs, not the OCR-tuned PNG `cropToBlob`), thumb generated at capture; palette read on the component uses the existing orchestrator unchanged.
- **Styling**: chips reuse the `FilterBar` chip style; strip uses `wire` cards; light + dark.
- **Accessibility**: "Capture component" flow keyboard-operable (CropTool already is); chips are `aria-pressed` buttons; strip items are links with accessible names "component: button, nav — from <post>"; focus moves to the form on confirm and to the new strip item on save.
- **Edge cases**: IndexedDB upgrade failure (v1 → v2 throws) → today's catch-all flips to in-memory and shows an empty library; the plan makes the upgrade version-aware **and** `db.ts` records why it fell back — `storageFallbackReason(): 'none' | 'unavailable' | 'upgrade-failed'` (set alongside `inMemory`) — so `Layout.tsx`'s `StorageBanner` can say "Storage upgrade failed — this session is in-memory; your saved entries are intact but not loaded" instead of the generic unavailable text (banner test for both reasons); capture on an entry whose parent image is missing (blob not found) → inline error; rect below `MIN_CROP_EDGE` → Use crop disabled (existing); deleting the parent removes children in one transaction; importing a component before its parent within the same file (ordering) or without any parent (skipped + counted); URL-less entries in the "Recent" row and cards; duplicate-check skipped without URL; a component's "Extract palette" degrades exactly like a design.
- **Performance**: the strip reads thumbs only — **eagerly**, by design: it renders only on the parent page, holds a handful of items, and is on screen as soon as it exists, so intersection gating (kept for the unbounded library grid) would add an observer per item for no saving (recorded at release); `listChildren` uses the `by-parent` index; cascade delete is one transaction.

## Type Definitions

```ts
type Kind = 'palette' | 'design' | 'component'
type ComponentTag = 'button' | 'nav' | 'card' | 'form' | 'input' | 'list' | 'modal' | 'table' | 'hero' | 'footer' | 'typography' | 'icon' | 'chart' | 'other'
interface Entry {
  id: string
  url?: string; platform?: Platform; shortcode?: string; author?: string   // absent together for URL-less captures and components
  kind: Kind; images: ImageRef[]; sourceImageId?: string                    // always one of THIS entry's images (a component's own crop)
  parentId?: string; parentImageId?: string; sourceRect?: NormalizedRect; componentTags?: ComponentTag[]   // provenance: parent entry, parent image, rect over it
  colors?: string[]; roleMap?: RoleMap; blockOverrides?: Record<string, string>; mockTemplate?: MockTemplateId
  paletteSource?: PaletteSource; crop?: { imageId: string } & NormalizedRect
  tags: string[]; note: string; createdAt: number; updatedAt: number
}
```

## Performance & Cost Impact

Negligible: one extra index, one extra image record per component (natural-size crop, typically < 1 MB), no new dependencies, no bundle growth beyond a few KB of UI.

## Backward Compatibility

- IndexedDB upgrade v1 → v2 adds an index only; existing data untouched.
- Export v1 files from v0.1.0/v0.2.0 import unchanged (all new fields optional; `url` present on every old entry).
- A v0.2.0 app importing a v0.3.0 file would reject `kind: 'component'` — forward-only, acceptable (single user).
