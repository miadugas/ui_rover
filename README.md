# ui_rover

**Version 0.3.0**

A personal UI/UX swipe file for Instagram and Threads posts. It turns saved posts into a browsable library of three entry kinds: **palette** entries (a post showing a color palette, read and previewed on a UI mock), **design** entries (a post showing a UI/UX design, kept with tags and notes), and **component** entries (a button, nav, card… captured as a rectangle out of a design screenshot, with its own image, tags and a link back to the post).

## How it works

There is no Meta/Instagram/Threads API and no scraping. The post URL is an optional bookmark (and the duplicate-detection key when present); the screenshot you paste or drop is the data. Everything runs in the browser — palette extraction happens on Canvas, entries persist in IndexedDB — and the only backup path is JSON export/import.

## Capture flow

1. Paste the post URL (optional — a screenshot alone can be saved).
2. Paste or drop one or more screenshots (carousels welcome).
3. Pick **palette** or **design**.
4. Save. For a palette entry, ui_rover reads the printed hex codes off the card automatically (auto-crop finds the card; OCR reads the codes), falling back to swatch-shape detection or whole-image color extraction when there's no text to read.
5. On the entry page: a review panel shows what was read (checkboxes, source badges) to Apply or Append; a **Crop** button lets you point the reader at the card by hand when auto-detection misses; swatches, a wireframe mock (11 templates) where every block is a touchpoint to recolor, and tags/notes.

OCR runs locally in the browser (Tesseract.js) — no network request, ever. Its runtime assets live in `public/ocr/`, generated by `predev`/`prebuild` (never committed), and add roughly 15 MB to `dist/`.

## Component capture

On a **design** entry, press **Capture component**, draw a rectangle over the selected screenshot, pick component chips (button, nav, card, form, input, list, modal, table, hero, footer, typography, icon, chart, other), add free tags and a note, and save. The component becomes its own library card (natural-size WebP crop + thumb) linked to its parent post, appears in the parent's Components strip, and can run the same palette read. Deleting a post deletes its components. The library filters by kind (**Component**) and by component type.

## Backup

Export produces `ui_rover-YYYY-MM-DD.json` with images inline (base64). Import either merges new entries (by id, and by URL when present) or replaces the whole library — replace requires confirming twice. Components whose parent post is not part of the result are skipped and counted as orphaned.
